# 要件定義書 — Privacy Asset Checker

## 1. 背景と課題

資産管理アプリの多くは、証券口座や銀行口座と連携するために**資産データをサーバーへ預ける**前提で作られています。一方で、

- 資産額・保有銘柄・口座の一覧は、個人情報の中でも特に機微な情報である
- 口座連携のための認証情報を第三者に渡すことに抵抗がある人は少なくない
- 「月 1 回、ざっくり総額と構成比を把握したい」だけなら、自動連携は過剰である

という層には、選べる選択肢がほとんどありませんでした。

## 2. 目的

**「サーバーに預けない」ことを最優先にした、端末内で完結する資産管理アプリ**を提供する。

| 目的 | 達成指標（設計上の約束） |
|---|---|
| データを外に出さない | アプリ専用のサーバーを持たない。通信は「ストア課金」「LAN 引き継ぎ」の 2 つだけ |
| 端末内でも守る | DB 全体の暗号化・生体認証ロック・画面遮蔽 |
| 続けられる | 2 回目以降の記録を数秒で終えられる（前回の 1 タップ複製）。月 1 回のリマインダー |
| 失っても戻せる | 暗号化バックアップを**無料**で提供 |

## 3. 対象ユーザー

| ペルソナ | 特徴 | 主に使う機能 |
|---|---|---|
| NISA・iDeCo で積立中の会社員 | 複数の証券口座と銀行口座を持つ。月 1 回、資産の全体像を見たい | 資産配分・推移・1 タップ複製 |
| 資産を他人に知られたくない人 | 口座連携サービスに認証情報を渡したくない | 端末内保存・生体認証ロック |
| 積立の効果を知りたい人 | 増えたのが入金のおかげか相場のおかげかを分けて見たい | 入金額の記録・元本ライン（Pro） |

## 4. 機能要件

| ID | 機能 | 内容 | プラン | 画面 |
|---|---|---|---|---|
| F-01 | 資産の記録 | 口座 × カテゴリ × 日付で評価額を記録する | Free | S31 |
| F-02 | 前回の複製 | 前回の内訳を 1 タップで引き継ぎ、変わった金額だけ直す | Free | S31 |
| F-03 | 総額だけで開始 | 口座を作らずに総額だけで記録を始められる | Free | S31 |
| F-04 | CSV 取り込み | SBI / 楽天の保有商品一覧 CSV を端末内で解析し、カテゴリ別に取り込む | Free | S32 |
| F-05 | 資産配分 | 総資産・前回比・カテゴリ構成比（ドーナツ）・口座別内訳 | Free | S10 |
| F-06 | 資産推移 | 月別の評価額推移 | Free：直近 3 ヶ月 ／ Pro：全期間 | S20 |
| F-07 | 入金額と元本ライン | 入金額を記録し、評価額を「元本」と「運用損益」に分ける | Pro | S20, S31 |
| F-08 | 目標額 | 目標資産額を設定し、達成率と残額を表示する | Pro | S10, S40 |

### プラン設計の考え方

| 方針 | 内容 |
|---|---|
| データを守る機能に課金しない | バックアップ・生体認証ロック・リマインダーは Free。端末内完結は端末を失うと全損するため、唯一の救済手段に値段をつけない |
| 深掘りする機能は有料 | 全期間の推移・元本ライン・目標・口座無制限 |
| 約束できないものを売らない | CSV 取り込みは証券会社の書式変更で壊れうるため、Free のベストエフォート提供と明記 |
| サブスクにしない | サーバー維持費が 0 円なので、月額を取り続ける理由がない |

## 5. 非機能要件

| 区分 | 要件 | 実現方法 |
|---|---|---|
| 機密性 | 保存データを暗号化する | SQLCipher（AES-256）。鍵は Keychain / Keystore |
| 機密性 | 外部へ送信しない | HTTP クライアント・解析 / 広告 SDK を持たない |
| 機密性 | 画面ののぞき見を防ぐ | `FLAG_SECURE` ／ iOS ブラー |
| 完全性 | バックアップの改ざんを検知する | AES-256-GCM の認証タグ |
| 完全性 | 書き込み途中で壊れない | 複数テーブルにまたがる書き込みはすべてトランザクション |
| 可用性 | 端末を失ってもデータを戻せる | 暗号化バックアップ（Free） |
| 可用性 | 認証手段がない端末で締め出さない | 認証不可の端末ではロックを素通し |
| 性能 | 鍵導出（1〜2 秒）で UI を止めない | `Isolate.run` で別 isolate に逃がす |
| 保守性 | ロジックを端末なしで検証できる | 純粋関数として切り出し、単体テスト 81 ケース |
| 保守性 | 静的解析の警告ゼロ | `flutter analyze` 警告 0 |
| 互換性 | 旧スキーマから移行できる | `onUpgrade` で冪等にテーブル追加（v1 → v2 を実機確認） |
| 対応 OS | Android 7.0（API 24）以上 ／ iOS | `minSdk 24`（`flutter_secure_storage` の AES-GCM と `BiometricPrompt` のため） |

## 6. あえて作らなかったもの

| 見送ったもの | 理由 |
|---|---|
| 年別グラフ | 3 年目までは月別と同じ形にしかならず、トグルの分だけ画面が重くなる |
| カテゴリ色のユーザー編集 | 選ばせてもグラフは読みやすくならず、破綻する配色を選べるようになるだけ |
| 口座の「休止中」状態 | 覚える概念が 1 つ増える割に使われない |
| 記録のメモ欄 | 入力元は `source` 列で足りている |
| ホーム画面ウィジェット | ロック画面に総資産が出る時点で、このアプリの前提と矛盾する |
| 口座の自動連携 | サーバーを持たない方針と両立しない |
